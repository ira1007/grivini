Operating guide

A practical guide to loading ephemeris, interpreting the visualization, analyzing service windows, and understanding the preview assumptions.

01

Quick start

  1. Open the application and allow the 3D Earth to load.
  2. Use Load new SIB19 demo to restore the included Cupertino UE and two-satellite scenario.
  3. Review the configured minimum elevation, carrier frequency, duration, and analysis step.
  4. Select Calculate and plot after changing inputs.
  5. Use playback controls or the timeline to propagate the scenario.
  6. Select Analyze service window to generate service duration and mobility events.
02

Satellite inputs

Each satellite card supports two input types:

Position / velocity

ECEF position and velocity entered either as raw PositionVelocity-r17 integers or engineering units.

Orbital elements

Semi-major axis, eccentricity, argument of periapsis, longitude/RAAN, inclination, and mean anomaly entered as raw Orbital-r17 values or engineering units.

The converter buttons populate the alternate representation and display copyable SIB19-oriented output plus engineering values.

03

Display layers

  • Straight UE–satellite LOS links: a direct line segment from the UE to each displayed satellite.
  • Orbit paths: instantaneous orbital rings when valid elements are available.
  • Sub-satellite points: current satellite projection on the Earth.
  • Earth-rotating ground track: projected trajectory in the Earth-fixed frame.
  • Future trajectory: upcoming propagated path.
  • Time markers and direction: one-minute markers and a forward-direction indicator.
  • Orbital-element guide: visual references for the equatorial plane, ascending node, periapsis, and current radius vector.

05

Service analysis

The preview evaluates each satellite at the configured analysis step. A satellite is service-eligible when its elevation is at or above the minimum elevation. The serving satellite is the eligible satellite with the highest elevation.

The resulting summary reports time in service, outage duration, serving changes, maximum elevation per satellite, and service time per satellite. The event log records horizon crossings, threshold crossings, service entry or loss, and serving-satellite changes.

07

Assumptions and validation

Engineering preview

The application uses a two-body Keplerian propagation model and specific frame/scaling interpretations implemented in the tool. Verify input epoch, units, reference frames, model suitability, and calculated results independently before formal test planning or conformance use.
